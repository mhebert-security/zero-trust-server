zero-trust-server

A sane person would have used nginx.

mhebert.dev is served by a web server I wrote in Rust, starting at the TCP socket: the HTTP/1.1 parser, the rustls TLS handshake, the session cookie, and the proof of work that stood between you and this sentence. The code is public, and it has to be. A server whose claim is that you can trust it cannot hide the source and keep the claim.

The constraints are the pitch. TLS is pinned to 1.3 and handled by rustls, one audited crate, rather than OpenSSL, which is a second operating system. The parser is mine, not hyper's, so a malformed request is a file I can open, not a library I must trust. There is no unsafe in the server. Entry requires solving a SHA-256 puzzle with twenty leading zero bits, a few seconds for a person and an expensive habit at scale, and the cookie that follows proves the puzzle was solved, never who solved it. The server admits 128 connections at a time, gives each five seconds, and caps solve attempts per IP address, so one loud visitor cannot close the site for everyone else. Every request writes one structured line to the journal. The site can be asked what it did.

None of this was the efficient choice. A CDN in front of nginx would have been live in an afternoon, watched by more eyes than my code will ever have. That is the real cost of going by hand, and the only honest answer to it is to hide nothing. Read the code, find the flaw, tell me. The bet of this whole site is that a person who can be checked is worth more than a product that cannot.
