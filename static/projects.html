zero-trust-server

A sane person would have used nginx.

A proof of work gate and a pass or fail cookie are a beginning, not a destination. The version this project is working toward takes years: nodes that issue and verify attestations with no central authority, an enclave that keeps the session key out of unprotected memory, a proof assistant checking the cryptographic core, proof of work that prices each request by the threat it carries instead of a fixed constant, and a session that is a signed set of permissions rather than a pass or fail. None of that is a roadmap; it is where the code already leans, and every step ships in the open.

cyber-news-aggregator

The feed that knows what it is watching.

Ten cybersecurity sources fetched every six hours, stored in SQLite, and served behind the same proof of work gate as everything else on this server. Each item is tagged by ATT&CK category so a CVE advisory and a breach report do not sit in the same pile. The fetcher runs as a hardened NixOS oneshot service. The route enforces session auth. Nothing in this stack is shared with the fetcher except a read-only view of the database.

modbus-dnp3-traffic-analysis

The write that can stop a line.

Modbus and DNP3 still move control traffic in the clear, built for a time when the network was a locked room. This project builds a baseline of normal traffic on those links and flags the message that does not belong, so the anomaly shows up while it is still a packet and not yet an outage. The detection starts from the physics of the place, not from a list of known attack names.

sigma-detections-attck

Rules that say what they caught.

A detection rule is only as trustworthy as the framework that names what it catches. Every Sigma rule here maps to a MITRE ATT&CK technique, so a hit answers which stage of an intrusion it belongs to, and a rule leaves the experimental pile only after a recorded validation run. Naming the part of the kill chain is how a single alert becomes a story an analyst can act on.

github.com/mhebert-security/sigma-detections-attck

yara-rules-malware-detection

Code that describes code.

A hash tells you a file changed and nothing about why, and malware rewrites itself faster than any checksum can follow. These YARA rules describe the strings and structures a family keeps as it mutates, so a fresh sample still answers to the old name. They are written to run cheap, because the box doing the scan may be an edge device with better things to do.
