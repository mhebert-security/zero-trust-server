ICS Incident ATT&CK Mapping

A kill chain table mapping five ICS incidents to MITRE ATT&CK for ICS.

Every technique used in each incident is listed by tactic. A tactic is the attacker's goal, and a technique is a specific way of reaching it. Each row also names the CVE, short for Common Vulnerabilities and Exposures and the public identifier assigned to a known security flaw, that enables the technique where one exists. The CVE column is deliberately empty for most rows. That emptiness is the point of the table.

This page is a companion to Reading the Incident Reports: Five ICS Attacks That Defined the Field, from Module 1, Article 2 of the From Bedside to Substation series.

What the CVE Column Says

Across 37 technique instances, four have a CVE behind them, and all four belong to a single incident, Stuxnet's Windows and Siemens WinCC layer. Every technique the attack used after it reached the PLC, short for programmable logic controller, has no CVE, because the Siemens S7 protocol accepts control commands as designed. For the other four incidents, the CVE column is empty at every row.

The B. Braun mapping (T0855) is the same technique Industroyer used to open breakers in Kyiv. The BD Alaris mapping (T0839) is the same technique Stuxnet and TRITON used on their respective controllers. The CVE exists for the pump. It does not exist for the protocol.

Verification Status

Technique IDs are written from memory and spot checked. Before this table is cited elsewhere, audit every ID against the ATT&CK for ICS matrix at attack.mitre.org/matrices/ics/.

The CVE-2017-14013 series for the Triconex controllers is not yet reflected as a row. Those CVEs describe vulnerabilities adjacent to the TRITON attack path rather than the path itself, and the table currently records the path. If you want them included, add a secondary section rather than a technique row.
